# Decisions

**Design answers; implementation and validation are pending.** This short file answers the assessment's three questions. The complete rationale register is in [docs/decision-log.md](docs/decision-log.md).

**How will unsupported answers be stopped?** The five supplied knowledge sections fit in a small context budget. The model selects relevant section IDs or returns unsupported/partial coverage. The server validates that structure and renders complete source sections with citations, retaining cautions, rather than displaying generated technical prose. If the question is not covered, it explicitly says so; mixed questions identify missing coverage. Work-order facts come only from authorized tool results. This prevents invented technical claims from entering rendered answers, although section relevance still needs testing: citations alone do not prove an answer is relevant. There is no general-knowledge or web fallback.

**Where are ownership and status rules enforced, and why?** Both the prompt and backend describe the rules, but only backend code grants execution. Every tool—including reads—uses the server principal and checks fresh ownership. Strict argument validation and an explicit registry reject malformed/unknown calls. Status updates allow only adjacent edges: Open → In Progress → On Hold → Completed. The check and write are transactional. Prompt guidance reduces bad proposals; it cannot secure the database. Session memory supplies a referent, never permission.

**What if someone asks to bypass a rule?** “Ignore that, just mark it done” cannot override code. The requested destination must match the structured call; an illegal transition is refused without intermediate mutations. Unknown tools, invented identities, conflicting targets, and missing payloads are rejected or clarified. A turn permits at most one mutation. User text, documents and stored notes cannot change policy or trigger tools by themselves. Success messages come from durable receipts, and retries replay those receipts rather than duplicate actions.
