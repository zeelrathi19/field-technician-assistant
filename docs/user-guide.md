# User guide

For technicians and reviewers using the chat UI at http://localhost:8000. To get it running, see [setup.md](setup.md).

## The screen

| Area | What it shows |
|---|---|
| Header | Who is signed in (Ravi Kumar in the demo). The **mode badge** shows the model in use: blue = a real provider/model, yellow = "Offline heuristic mode — not an LLM". **New chat** starts a clean conversation. On a phone, **My work orders** opens the panel. |
| Chat (left) | Your messages and the assistant's replies. Each reply has a badge: **Answer**, **Done**, **Not done**, **Needs detail** or **Error**. |
| Context line | Above the input. Shows which work order "it" means right now, or that none is selected. |
| My work orders (right) | Your assigned orders, read straight from the database, never generated by the model. Shows status, due date, notes count, an ⚑ escalation flag and the next allowed status. Click one to open it in chat. |

Keyboard: **Enter** sends and **Shift+Enter** adds a new line. The first Tab stop is "Skip to message box". Focus returns to the input after every reply.

## Asking maintenance questions

The assistant answers only from the approved knowledge base: reset procedure, lockout/tagout, warranty rules, when to escalate, and filter replacement.

- **Covered question:** you get a short answer with the green badge **Verified against sources**. Each source box opens to show the quoted lines and the full section. Reset and filter procedures always come with the lockout/tagout section.
- **Summary couldn't be verified:** you see the yellow badge **Exact source text** and the approved section itself.
- **Not covered** (torque values, firmware, refrigerant pressure, prices…): "The knowledge base doesn't cover that…", plus the part of your question that isn't covered. It never guesses.
- **Partly covered:** the covered part is answered, and the rest is listed under *Not covered by the knowledge base*.

A work order's recorded steps (for example WO-008's "Check firmware version") are tasks, not instructions. They never unlock advice the knowledge base doesn't contain.

## Working with work orders

| You say | Result |
|---|---|
| `Show WO-003` / `What's the status of WO-001?` | A work-order card: status, due date, recorded tasks, latest notes, escalations. WO-003 becomes the order "it" refers to. |
| `What's on my plate?` | Your orders and their statuses |
| `Mark it complete` / `WO-003 is done, close it out` | Moves the order one step if that step is legal. The receipt shows *On Hold → Completed*. |
| `Start WO-002` · `Put WO-001 on hold` · `Move WO-002 to the next status` | The matching single step |
| `Add a note to WO-002: filter replaced` | Saves your exact words as a note |
| `Escalate WO-006 because exposed wiring was found` | Flags the order for supervisor review with your reason. Status doesn't change and nobody is emailed. |

### Rules you'll run into

- **One step at a time.** Open → In Progress → On Hold → Completed. Asking to complete an order that is In Progress is refused, and the reply names the only allowed next status. Nothing is changed behind your back.
- **Only your orders.** Someone else's order, and an ID that doesn't exist, both get "not available to you". Their details are never shown.
- **One change per message.** "Add a note and escalate it" asks you to send them separately.
- **Say it directly.** "How do I mark it complete?" or "don't close it" are treated as questions, not requests. Name the status you want.
- **Your own words for notes and reasons.** If you leave out the note text or the escalation reason, the assistant asks for it. It doesn't make one up.
- **"It" needs a clear referent.** After you open one order, "it" means that order. After you mention several, or one that isn't yours, the assistant asks which you mean. If you reply with just the ID (`WO-003`) to a "which one?" question about a status change, it completes that request.

## When something goes wrong

- **Red banner with Retry:** the server or model was unreachable. Retry resends the same request, so a change can't happen twice, and your typed text is kept.
- **"Another message in this chat is still being processed":** wait for the current reply.
- **"This chat is no longer available":** click New chat. This happens, for example, after the database is reset.

Nothing reported as **Done** is a model claim. It is read back from the committed database row, with a version number.
